# 2026 H 题 K230 视觉与串口交接说明

版本：v1，2026-07-30

这份包只负责 K230 视觉端与 MSPM0-B 之间的接口。请先完成 UART 假坐标测试，
再把同一发送模块接入钢球识别，最后才叠加图传，避免同时排查多个问题。

## 一、唯一有效的接线

当前 K230 是源山派 Lite/K230D，固定使用 UART2：

| K230 | 方向 | MSPM0-B |
|---|---|---|
| 物理 11 脚 / GPIO5 / UART2_TXD | → | PB3 / UART3_RX |
| 物理 13 脚 / GPIO6 / UART2_RXD | ← | PB2 / UART3_TX |
| 物理 9 脚 / GND | — | GND |

参数统一为 `115200, 8N1, 3.3 V TTL, 无流控`。

注意：

1. TX、RX 必须交叉。
2. K230、MSPM0-A、MSPM0-B 最终必须共地。
3. 不要把 K230 USB 口接到 MSPM0 Type-C 口代替 TTL 串口。
4. 不要把两块控制板的 3V3/5V 电源脚直接并接。
5. FPIOA 中写的是 GPIO5、GPIO6，不是物理排针编号 5、6。
6. UART2 只允许发二进制协议。日志继续用 CanMV IDE 的 `print()`，不要
   `uart2.write("debug...")`。

## 二、建议执行顺序

### 第一步：只测串口，不开摄像头

把 `01_UART单独测试` 目录中的两个 `.py` 文件复制到 K230 同一目录，
将 `main.py` 运行起来。它会循环发送：

```text
-100 mm, -50 mm, 0 mm, +50 mm, +100 mm
```

MSPM0-B 的接收测试固件应依次显示这些位置。完成这一步才能说明接线、波特率、
帧头和 CRC 都正确。

### 第二步：运行钢球识别集成模板

将 `02_钢球识别集成模板` 中的三个文件复制到：

```text
/sdcard/steel_ball/
```

文件为：

```text
main.py
h2026_uart_protocol.py
steel_ball_yolov8n_320.kmodel
```

先从 CanMV IDE 运行，不要立即设置上电自启。

### 第三步：标定像素到毫米

打开 `02_钢球识别集成模板/main.py`，先保持：

```python
CALIBRATION_READY = False
```

把球分别放在钢管左端基准、中心 O、右端基准，读取屏幕上的
`best center: x,y`。将左、右基准的 x 像素填入：

```python
PIPE_LEFT_X_PX = ...
PIPE_RIGHT_X_PX = ...
```

确认右端是步进电机/可升降端，然后改为：

```python
CALIBRATION_READY = True
```

坐标约定已经冻结：

- 中心 O 为 `0 mm`；
- 向右侧步进电机/可升降端为正；
- 向左侧固定铰点为负；
- 25 cm 钢管理论端点约为 `-125 mm`、`+125 mm`。

如果画面左右镜像或上下颠倒，只改模板顶部的：

```python
H_MIRROR = False
V_FLIP = False
```

不要通过颠倒坐标正负来修画面。

### 第四步：再加入图传

图传可以使用独立网络线程/任务，但不能长期阻塞识别循环。无论图传是否连接，
UART 都应持续发送：

- 识别到球：`valid=1`，发送位置和置信度；
- 没识别到球：`valid=0`，仍发送一帧；
- 推荐发送频率 20–50 Hz；
- 任意一次阻塞尽量小于 50 ms，绝不能超过主控的 150 ms 视觉超时。

## 三、K230 需要交付的最终结果

视觉同学完成后，请确认：

- [ ] 画面方向正确，钢管左/右与真实方向一致；
- [ ] 单球识别稳定，遮挡或无球时会清除 valid；
- [ ] 中心 O 显示约 `0 mm`；
- [ ] 球向步进电机端移动时 `x_mm` 增大；
- [ ] UART 连续运行 5 分钟无 CRC 错误；
- [ ] 图传打开/关闭都不影响 UART 超时；
- [ ] 只使用本包的 `h2026_uart_protocol.py` 生成数据帧。

## 四、已验证测试帧

调用参数：

```text
sequence=7
x_mm=-35
confidence=92
valid=1
pipe_visible=1
frame_id=0x1234
processing_ms=17
```

完整十六进制帧必须为：

```text
AA 55 01 10 07 08 DD FF 5C 03 34 12 11 00 B8 4C
```

CRC 使用 CRC-16/CCITT-FALSE。完整协议见
`03_协议与主控参考/H2026_UART_PROTOCOL.md`。
