# H2026 庐山派 K230 → 天空星 STM32F407VET6 串口通信交接说明

版本：2026-07-31  
适用程序：`D:\TUCHUAN\main.py`、`D:\TUCHUAN\vision_uart_publisher.py`

## 1. 当前用途

庐山派 K230 运行 YOLO11 钢球检测，把小球中心点通过 UART2 发送给
天空星 STM32F407VET6。当前发送的是经过短时运动延迟补偿后的“当前时刻中心点估计”，
与庐山派 LCD 上显示的绿色框和十字中心一致。

串口只负责发送坐标，不负责底盘和滚球闭环控制。

## 2. 接线

| 庐山派 40Pin | K230 功能 | 连接到 STM32F407VET6 |
|---|---|---|
| 物理 11 脚 | GPIO5 / UART2_TXD | STM32 所选 USART/UART 的 RX |
| 物理 13 脚 | GPIO6 / UART2_RXD | 可不接；需要双向通信时接 STM32 TX |
| 任意 GND 脚 | GND | STM32 GND |

注意：

- TX 和 RX 必须交叉连接，不能 TX 接 TX。
- 两块板必须共地。
- 串口信号按 3.3 V TTL 电平使用，禁止把 5 V 串口信号直接接入 K230。
- 当前协议是 K230 单向发送，因此只接 K230 TX、STM32 RX、GND 即可。
- 天空星板具体选择 USART1/2/3/6 中的哪一路、使用哪个引脚，必须以队友的
  CubeMX 配置和开发板原理图为准，本文不指定未核对的板级引脚。
- K230 40Pin UART2 不是电脑上的 USB/TPC 虚拟串口。

## 3. UART 参数

| 参数 | 当前值 |
|---|---|
| K230 串口实例 | UART2 |
| 波特率 | 9600 bit/s |
| 数据位 | 8 |
| 校验位 | 无 |
| 停止位 | 1 |
| 流控 | 无 |
| 数据类型 | ASCII 文本 |

即：`9600, 8N1, No Flow Control`。

## 4. 数据帧格式

```text
[x,y]\r\n
```

- `[`：帧头。
- `x`：十进制横坐标，范围 `0～799`。
- `,`：坐标分隔符。
- `y`：十进制纵坐标，范围 `0～479`。
- `]`：有效数据结束标志。
- `\r\n`：回车换行，十六进制为 `0D 0A`。

坐标系：

```text
(0,0) --------------------> x 增大
  |
  |
  |
  v
y 增大

右下角最大坐标为 (799,479)
```

示例：

```text
[400,240]\r\n
```

对应十六进制字节：

```text
5B 34 30 30 2C 32 34 30 5D 0D 0A
```

## 5. 发送时序与无目标行为

- 小球坐标发生变化时，最短发送间隔为 `50 ms`，最高约 `20 包/秒`。
- 小球坐标不变时，每 `100 ms` 至少重发一次有效坐标。
- YOLO 没有检测到小球或 AI 当前帧无效时，K230 **不发送任何坐标帧**。
- `[0,0]` 是合法坐标，不能把它当作“未检测到”。
- STM32 应通过接收超时判断目标丢失，建议超时值为 `200 ms`。
- 超时后应立即把视觉数据标记为无效，禁止继续使用最后一次旧坐标。

## 6. 坐标含义

当前发送值不是未经处理的原始 YOLO 框中心，而是：

```text
YOLO 检测中心
    + 连续帧速度估计
    + 本帧实际推理耗时补偿
    = 当前时刻中心点估计
```

补偿受到最大时间和最大像素限制；小球停止或运动方向反转时会快速取消旧方向
预测。STM32 端不要再增加很强的低通滤波，否则会重新引入明显位置滞后。

## 7. STM32F407 接收状态机参考

下面的解析逻辑与具体 UART 实例和引脚无关。队友先在 STM32CubeMX 中选择
一组没有被其他功能占用的 USART/UART RX 引脚，设置为异步模式
`9600, 8N1, No Flow Control`，然后生成 HAL 工程。

```c
#include <stdbool.h>
#include <stdint.h>

typedef enum {
    VISION_WAIT_HEADER = 0,
    VISION_READ_X,
    VISION_READ_Y
} VisionParseState;

typedef struct {
    VisionParseState state;
    uint16_t work_x;
    uint16_t work_y;
    bool have_x_digit;
    bool have_y_digit;

    volatile uint16_t x;
    volatile uint16_t y;
    volatile uint32_t last_packet_ms;
    volatile bool has_packet;
    volatile bool packet_updated;
} VisionUartReceiver;

static VisionUartReceiver gVision;

static void Vision_ResetWorkingFrame(void)
{
    gVision.work_x = 0U;
    gVision.work_y = 0U;
    gVision.have_x_digit = false;
    gVision.have_y_digit = false;
}

void VisionUart_InitParser(void)
{
    gVision.state = VISION_WAIT_HEADER;
    Vision_ResetWorkingFrame();
    gVision.x = 0U;
    gVision.y = 0U;
    gVision.last_packet_ms = 0U;
    gVision.has_packet = false;
    gVision.packet_updated = false;
}

/* 每收到一个 UART 字节调用一次；可以从 UART RX ISR 中调用。 */
void VisionUart_PushByte(uint8_t byte, uint32_t now_ms)
{
    if (byte == (uint8_t)'[') {
        Vision_ResetWorkingFrame();
        gVision.state = VISION_READ_X;
        return;
    }

    switch (gVision.state) {
    case VISION_WAIT_HEADER:
        /* 忽略 CR、LF、噪声和不完整旧帧。 */
        break;

    case VISION_READ_X:
        if ((byte >= (uint8_t)'0') && (byte <= (uint8_t)'9')) {
            gVision.work_x =
                (uint16_t)(gVision.work_x * 10U + (byte - (uint8_t)'0'));
            gVision.have_x_digit = true;
            if (gVision.work_x > 799U) {
                gVision.state = VISION_WAIT_HEADER;
            }
        } else if ((byte == (uint8_t)',') && gVision.have_x_digit) {
            gVision.state = VISION_READ_Y;
        } else {
            gVision.state = VISION_WAIT_HEADER;
        }
        break;

    case VISION_READ_Y:
        if ((byte >= (uint8_t)'0') && (byte <= (uint8_t)'9')) {
            gVision.work_y =
                (uint16_t)(gVision.work_y * 10U + (byte - (uint8_t)'0'));
            gVision.have_y_digit = true;
            if (gVision.work_y > 479U) {
                gVision.state = VISION_WAIT_HEADER;
            }
        } else if ((byte == (uint8_t)']') && gVision.have_y_digit) {
            /* 到 ']' 时提交一整帧；后面的 CR/LF 会自动被忽略。 */
            gVision.x = gVision.work_x;
            gVision.y = gVision.work_y;
            gVision.last_packet_ms = now_ms;
            gVision.has_packet = true;
            gVision.packet_updated = true;
            gVision.state = VISION_WAIT_HEADER;
        } else {
            gVision.state = VISION_WAIT_HEADER;
        }
        break;

    default:
        gVision.state = VISION_WAIT_HEADER;
        break;
    }
}

bool VisionUart_IsFresh(uint32_t now_ms)
{
    return (
        gVision.has_packet
        && ((uint32_t)(now_ms - gVision.last_packet_ms) <= 200U)
    );
}
```

### 7.1 STM32 HAL 单字节中断接入示例

9600 波特率下数据量很小，单字节接收中断足够使用。下面的 `huart2` 只是
占位示例，队友必须替换成 CubeMX 实际生成的句柄，不能因为 K230 使用
UART2 就默认 STM32 也必须使用 USART2。

```c
#include "main.h"

/* 按 CubeMX 实际配置替换，例如 huart1、huart2、huart3 或 huart6。 */
#define VISION_UART_HANDLE huart2

extern UART_HandleTypeDef VISION_UART_HANDLE;
static uint8_t gVisionRxByte;

void VisionUart_StartReceive(void)
{
    (void)HAL_UART_Receive_IT(
        &VISION_UART_HANDLE,
        &gVisionRxByte,
        1U
    );
}

void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == VISION_UART_HANDLE.Instance) {
        VisionUart_PushByte(gVisionRxByte, HAL_GetTick());
        (void)HAL_UART_Receive_IT(
            &VISION_UART_HANDLE,
            &gVisionRxByte,
            1U
        );
    }
}

void HAL_UART_ErrorCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == VISION_UART_HANDLE.Instance) {
        /* 发生噪声、帧错误或溢出后重新挂接接收。 */
        (void)HAL_UART_Receive_IT(
            &VISION_UART_HANDLE,
            &gVisionRxByte,
            1U
        );
    }
}
```

如果工程中已经存在 `HAL_UART_RxCpltCallback()` 或
`HAL_UART_ErrorCallback()`，必须把上述分支合并进去，不能再定义第二个同名
函数。

初始化顺序：

```c
HAL_Init();
SystemClock_Config();
MX_GPIO_Init();
MX_USARTx_UART_Init();       /* 使用 CubeMX 生成的实际初始化函数 */
VisionUart_InitParser();
VisionUart_StartReceive();
```

主控制循环读取一对一致坐标时，可以短暂屏蔽中断：

```c
bool VisionUart_ReadLatest(
    uint32_t now_ms,
    uint16_t *x,
    uint16_t *y)
{
    uint32_t primask = __get_PRIMASK();
    __disable_irq();

    bool has_packet = gVision.has_packet;
    uint16_t latest_x = gVision.x;
    uint16_t latest_y = gVision.y;
    uint32_t last_packet_ms = gVision.last_packet_ms;
    gVision.packet_updated = false;

    if (primask == 0U) {
        __enable_irq();
    }

    if (
            !has_packet
            || ((uint32_t)(now_ms - last_packet_ms) > 200U)) {
        return false;
    }

    *x = latest_x;
    *y = latest_y;
    return true;
}
```

使用示例：

```c
uint16_t ball_x;
uint16_t ball_y;

if (VisionUart_ReadLatest(HAL_GetTick(), &ball_x, &ball_y)) {
    /* ball_x/ball_y 有效，可以交给控制算法。 */
} else {
    /* 超过 200 ms 未收到坐标：视觉目标无效，禁止沿用旧坐标。 */
}
```

注意：

- `HAL_GetTick()` 默认提供 1 ms 系统时基，满足本协议超时判断。
- UART 中断里不要使用 `printf`、`sscanf`、动态内存或阻塞等待。
- 若控制工程已经修改 HAL Tick 来源或关闭 SysTick，需改用工程自己的 1 ms
  单调计数。
- 如果使用 FreeRTOS，应在任务中读取完整坐标；ISR 仍只负责喂入字节。

## 8. 串口助手测试

使用 USB-TTL 接收时：

- USB-TTL RX 接庐山派物理 11 脚。
- USB-TTL GND 接庐山派 GND。
- 串口助手设置为 `9600, 8N1`。
- 接收模式选择“文本模式”。

检测到小球时应看到：

```text
[376,221]
[381,220]
[389,219]
```

没有检测到小球时接收区停止刷新属于正常行为。

## 9. 常见故障

| 现象 | 优先检查 |
|---|---|
| 完全收不到数据 | 是否检测到球、是否共地、TX 是否接到对方 RX、是否打开正确串口 |
| 显示十六进制数字 | 串口助手是否误选 HEX 接收模式 |
| 偶尔出现残帧 | 接收端必须等 `[` 重新同步，并在 `]` 才提交数据 |
| 坐标一直不失效 | STM32 是否实现 200 ms 接收超时 |
| 坐标反应再次变慢 | STM32 是否又增加了强低通/滑动平均滤波 |
| 坐标方向相反 | 控制端是否正确理解 x 向右增大、y 向下增大 |
