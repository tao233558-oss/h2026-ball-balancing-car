# K230 部署与图传

## 版本选择

本目录的入口是从赛时YOLO11备份整理的ASCII适配版，目标为庐山派K230、ST7701 LCD和当前STM32 V17接口。保留备份的CanMV v1.6库调用方式；不是对所有CanMV固件版本的通用保证。原YOLOv8参考项目另有v1.8部署说明，不要混用两套模型、库和运行结果。

## TF卡文件

```text
/sdcard/
    main.py                    ← vision/k230/main.py
    vision_ascii_uart.py       ← 同目录
    target_selection.py        ← 同目录
    SmoothWBCRtsp.py           ← 同目录
    yolo11_gq_classes.txt       ← 同目录，现有类别为GQ
    local_config.py            ← 复制local_config.example.py并填本地AP配置
    yolo11_gq_320.kmodel        ← 当前缺失，须取同学对应YOLO11权重
```

CanMV环境还须提供`libs.PipeLine`、`libs.YOLO.YOLO11`及其AI2D/KPU依赖，和Sensor/Display/Media/VENC库。原TF备份只包含局部YOLO库，不是完整系统固件。不要为了补依赖把旧YOLO.py盲目覆盖到新固件。

## 先验证画面，再验证控制接口

1. 备份板上现有TF卡内容。先在IDE中运行，不立即覆盖已验证的自启程序。
2. 确认模型与标签匹配、LCD显示正常、钢球检测框方向与实际相符。
3. K230物理11脚GPIO5/TX接STM32 PA3/USART2_RX，并共地。GPIO6/RX只做UART映射，可不接线。使用3.3V TTL逻辑。
4. 用串口助手9600、8N1看`[400,240]`等绝对像素坐标。拿走球后应停止输出，不能输出伪造的`[0,0]`表示丢失。
5. 在STM32上先只看坐标和帧龄，确认超时，再重做37/351/658等三点标定。相机位置、镜像、ROI或显示尺寸变化后不能照搬旧标定。
6. 完成摄像头、串口、急停的独立验证后，才让执行机构参与联调。

## 图传

程序通过K230建立Wi-Fi AP，名称默认`LushanPi_RTSP`。本地密码放在`local_config.py`，该文件已被Git忽略。主程序仍保留占位密码，部署时应替换。

客户端连上AP后，用VLC打开LCD/日志显示的RTSP地址。历史常见地址是`rtsp://192.168.169.1:8554/test`，实际地址以板上网络配置为准。

| 参数 | 整理版配置 |
|---|---|
| LCD | 800×480 |
| 相机配置帧率 | 30 fps，非实测推理帧率 |
| AI采集/模型输入 | 320×180 / 320×320 |
| 置信度/NMS/候选上限 | 0.50 / 0.45 / 3 |
| RTSP编码 | H.264，目标12 fps，码率配置800，GOP12 |
| 状态日志 | `/sdcard/stream_status.txt` |

RTSP运行在辅助线程，通过限帧、编码超时与释放缓冲减小负担。12 fps是配置值，不能写成已测得的稳定输出或零延迟。图传异常时可以先停止RTSP隔离问题，保留本地推理及串口观察；不应为提高画面帧率牺牲坐标新鲜度。

## 常见问题

| 现象 | 检查 |
|---|---|
| Required file not found | YOLO11权重或标签路径是否齐全 |
| invalid kmodel / 不支持算子 | 模型架构、转换器与板端runtime是否匹配 |
| 有框但串口无数据 | GPIO5、共地、9600、框中心是否落在800×480范围 |
| 画面停止但控制仍认为有效 | 是否还有旧进程重复发旧坐标；当前协议没有图像序号 |
| 图传卡顿 | 独立测试推理、LCD和RTSP；检查供电、线程、缓冲及Wi-Fi环境 |
| 球移走后仍有框 | 当前模型误检，须检查高光/螺钉/圆孔等负样本，不是串口超时问题 |
