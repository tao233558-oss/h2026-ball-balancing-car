# E2025 顶层故障管理器

## 解决的问题

此前电机保护能够关闭 PWM 和 PB16/STBY，但 E2025 状态机不知道具体原因，OLED 可能继续显示 `RUNNING`，直到任务完成或超时。

现在 `user/e2025_fault_manager.c` 会把电机、云台和 K230 的安全状态统一映射为 `e2025_fault_t`。状态机保存故障原因并关闭全部逻辑输出，OLED 第4行显示状态和简短原因。

## 故障码

| OLED文字 | 含义 |
|---|---|
| `E-STOP` | 运行中按下SW4 |
| `NO FB` | 两侧电机有目标但编码器都没有反馈 |
| `LEFT FB` | 左轮有目标但左编码器反馈丢失 |
| `RIGHT FB` | 右轮有目标但右编码器反馈丢失 |
| `SPEED` | 左右轮实际计数与目标比例持续不匹配 |
| `LEFT DIR` | 左编码器方向与命令相反 |
| `RIGHT DIR` | 右编码器方向与命令相反 |
| `AIM STOP` | 云台适配层急停锁存 |
| `K230 LOST` | 本次瞄准任务收到过新帧，随后通信断开 |
| `INTERNAL` | 空输入、非法任务或未知子系统错误 |

## 停车与状态时序

电机安全不能等待状态机处理，因此采用两级时序：

1. 编码器保护发现故障的当前 10 ms 周期，立即把左右 PWM 清零并拉低 PB16/STBY。
2. 同周期末尾向 E2025 提交具体故障码。
3. 下一次 10 ms 状态机周期进入 `E2025_STATE_FAULT`，关闭驱动、循迹、云台和激光逻辑输出。

所以实际电机关闭延迟为0个额外控制周期，状态文字更新延迟最多1个控制周期。

## SW4急停

运行中按下SW4时，状态机直接进入：

```text
ABORT E-STOP
```

电机和云台适配器也会锁存各自的急停。只松开按键不能恢复真实执行器；必须复位芯片，防止误操作后直接重新启动。

## K230掉线判定

K230未上电或任务刚开始等待第一帧时不会立即报错，否则4秒搜索任务会在正常等待阶段误报。

只有满足以下条件才产生 `K230 LOST`：

- 当前任务确实需要瞄准；
- 本次任务已经收到过至少一个新序号的正确帧；
- 随后K230链路超过200 ms没有正确帧并进入断开状态。

云台/激光安全适配层仍会在100 ms无新帧时先停止输出，因此K230掉线也遵循“先安全关闭，后更新顶层状态”。纯循迹任务不依赖K230，不会因为相机断线而停止。

## OLED示例

```text
FAULT NO FB
FAULT K230 LOST
ABORT E-STOP
```

任务重新开始时顶层故障文字会清除，但电机和云台适配器的硬故障仍各自锁存。因此编码器故障或急停后，即使菜单允许重新选题，执行器仍不会恢复，直到芯片复位。

## 离线回放

```powershell
python offline_tools\e2025_fault_manager_sim.py
```

结果位于 `output/e2025_fault_manager_sim/summary.json`。测试覆盖所有电机故障映射、当周期停车/下一周期状态更新、K230会话判定、纯循迹任务隔离、云台急停和SW4可见原因。

## 硬件验证顺序

1. 不接电机主电源，确认OLED能显示模拟/注入的故障原因。
2. 车轮悬空运行双轮诊断，逐一拔掉左、右编码器验证 `LEFT FB`、`RIGHT FB`。
3. 两侧编码器都断开，确认出现 `NO FB` 且PB16/STBY为低。
4. 运行时按SW4，确认当周期停车并显示 `ABORT E-STOP`。
5. K230正常出帧后拔掉串口，确认云台先停、随后出现 `K230 LOST`。
6. 故障后尝试重新选题，确认电机/云台不会绕过锁存重新启动。
