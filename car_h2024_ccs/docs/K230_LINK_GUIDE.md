# K230 通信隔离层

## 当前结论

K230 的二进制协议解析已经从 UART0 中断中拆出，放入与硬件 UART 无关的 `user/k230_link.c`。当前默认配置为：

```c
#define E2025_ENABLE_K230_UART0_BRIDGE 0
#define E2025_ENABLE_K230_UART2 0
```

因此 PA10/PA11 上的 UART0 默认只服务板载 CH340 调试口和旧 ASCII 命令，不再把电脑串口数据送入 K230 二进制解析器。

K230 最终专用接口已分配为 UART2：`PB15=UART2_TX`、`PA22=UART2_RX`、115200 8N1。初始化和接收 ISR 已接入条件编译，但在实物接线验证前保持关闭。

接线方向：

- 庐山派物理 `11` 脚（`GPIO5/UART2_TXD`）→ MSPM0 `PA22/UART2_RX`；
- MSPM0 `PB15/UART2_TX` → 庐山派物理 `13` 脚（`GPIO6/UART2_RXD`）；
- 公共地建议使用庐山派物理 `9` 脚 GND，组成同侧连续的 9/11/13 三针接口；
- 两板 GND 必须相连，逻辑电平必须为 3.3 V TTL。

## 为什么不能继续共用 UART0

UART0 的 PA10/PA11 已连接天猛星板载 CH340。如果 K230 与 CH340 同时连接并驱动同一根 RX 线路，可能出现：

- 两个发送端电气冲突；
- 电脑调试字符被误当成二进制帧；
- K230 数据混入串口日志；
- CRC 错误和偶发重同步，难以判断是代码还是接线问题。

兼容开关只用于编译和临时实验，不代表推荐接线。正式 PCB 必须按 PB15/PA22 的独立 UART2 方案布线。

## 链路层接口

未来确定专用 UART 后，其接收中断只需要把每个字节交给：

```c
k230_link_push_byte(received_byte);
```

10 ms 控制中断调用：

```c
k230_link_tick_10ms();
```

应用层通过 `k230_link_get_snapshot()` 原子读取最后一帧和链路统计。模块内部使用发布序号保护，避免 UART 中断更新一半时主程序读到字段混合的坐标。

## 统计内容

`k230_link_status_t` 提供：

- 接收字节总数；
- CRC/版本正确帧数；
- 错误帧数；
- 重复序号帧数；
- 根据帧序号估算的丢帧数；
- K230 重启或大幅倒退次数；
- 最后一帧年龄和通信连接状态。

序号从 255 回到 0 会被识别为正常回绕，不会误报重启。

## 两级超时

- 瞄准安全适配层：超过 100 ms 没有新序号帧，停止云台并关闭激光许可。
- K230 通信链路：超过 200 ms 没有 CRC 正确帧，`connected=0`，应用层不再取得缓存坐标。

通信链路断开后，主程序会清除“已见序号”状态。K230 重启并重新连接时，即使第一帧序号与断线前相同，也会被当作本次连接的新帧。

## UART2 正式路径

只有显式设置：

```c
#define E2025_ENABLE_K230_UART2 1
```

E2025 初始化才会启用 UART2，UART2 ISR 会将 PA22 收到的每个字节送入 `k230_link_push_byte()`。当前已完成该开关为 0 和为 1 两种配置的编译验证，尚未完成真实 UART 波形和通信验证。

## UART0 兼容桥（禁止用于正式 PCB）

只有显式设置：

```c
#define E2025_ENABLE_K230_UART0_BRIDGE 1
```

UART0 中断才会把 PA11 收到的字节送入 K230 链路层。此时旧 ASCII 接收被关闭，避免同一字节同时进入两个解析器。

该路径只用于条件编译验证。没有完成 CH340 与 K230 电气隔离前，不要按此配置接线或烧录运行。

## 离线回放

```powershell
python offline_tools\k230_link_sim.py
```

结果位于 `output/k230_link_sim/summary.json`，覆盖分片帧、前导噪声、CRC 损坏、重复/丢失帧、序号重启/回绕以及断线重连。

## 硬件回来后的接入顺序

1. 断电检查庐山派物理 11 脚→PA22、PB15→庐山派物理 13 脚，以及物理 9 脚 GND→公共地；确认没有接到 PA10/PA11，也没有误接物理 12 脚 CTS。
2. 确认 K230 与 MSPM0 均为兼容的 3.3 V 逻辑。
3. 将 `E2025_ENABLE_K230_UART2` 改为 1，重新编译但先不连接云台和激光。
4. 示波器确认庐山派物理 11 脚上有 115200 8N1 波形，且 PA22 电平不超过 VDD+0.3 V。
5. 先不接云台和激光，通过统计确认错误帧、丢帧和重启计数。
6. 连续运行并拔插 K230，确认 100 ms 瞄准停止和 200 ms 链路断开均生效。
7. 通信稳定后，再进入云台单轴和激光互锁测试。

当前阶段只完成最终引脚分配、软件隔离、回放和两种开关配置的编译验证，没有证明真实 UART 接线已经可用。完整冲突审计见 `UART_PIN_CONFLICT_AUDIT.md`。
