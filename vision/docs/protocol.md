# 视觉坐标与串口接口

## 当前STM32 V17接口

```text
K230 UART2 TX: GPIO5，40Pin物理第11脚
STM32 USART2 RX: PA3
共同GND，3.3V TTL，9600 bit/s，8N1
ASCII字节: [x,y]\r\n
示例: [400,240]\r\n
HEX: 5B 34 30 30 2C 32 34 30 5D 0D 0A
```

x范围0～799，y范围0～479，原点左上，x向右、y向下。它们是LCD显示坐标系中的像素，不是毫米，也不是相对屏幕中心的正负偏移。STM32当前主要用x参与控制，但解析器要求x/y两个字段齐全。

坐标变化时最短发送间隔50 ms；同一坐标只有在收到新检测结果时才可每100 ms重发。无检测或无效框时静默。`[0,0]`是合法位置，不是无效标志。STM32当前实际超时300 ms；视觉同学原说明建议200 ms，本文按归档V17源码说明，不改控制端参数。

新发送模块不保留可由独立poll无限重发的旧检测缓存，每次发送都由调用者提交新采集帧的结果。这仍不能在协议层证明图像更新：若调用者误把同一旧结果反复当新帧提交，STM32也无法识别。后续升级可增加图像帧序号、采集时间和有效位，须两端同时升级。

## 毫米标定在主控端

已记录左端37 px、中点351 px、右端658 px，对应−125/0/+125 mm。分段映射为：

```text
p <= 351: x_mm = -125 + (p - 37) * 125 / (351 - 37)
p >  351: x_mm =          (p - 351) * 125 / (658 - 351)
```

像素p与物理x_mm的单位应分开写。换视角、移动支架、改镜像/ROI或输出尺寸都会影响标定。

## 历史格式区分

| 文件/阶段 | 输出 | 用途 |
|---|---|---|
| `vision/k230/main.py`整理入口 | 9600，`[x,y]`绝对像素 | 对齐当前STM32接收端，尚需模型与板端验收 |
| `output/k230_deploy_gpio5_v2`现存备份 | 115200，`[ball,X,CONF,FLAGS]` | MSPM0阶段文本实验，X是有符号像素偏移 |
| 视觉V2交接包/早期TF备份 | AA55 V2二进制帧 | 历史联调，不能直接喂给V17 ASCII解析器 |
| `h2026_uart_protocol` | AA55早期二进制协议 | 双板阶段协议测试 |

文件夹名带v2不代表内容一定仍为二进制，须检查`vision_uart_publisher.py`中实际打包语句。原始历史文件保留，不静默覆盖。

同学2026-07-31交接说明还描述了速度估计与推理耗时补偿。对应最终主程序未同步到本机，整理入口只用新帧的实际检测中心，发送与LCD十字共用同一坐标计算；不宣称复刻了未知的预测模块。
