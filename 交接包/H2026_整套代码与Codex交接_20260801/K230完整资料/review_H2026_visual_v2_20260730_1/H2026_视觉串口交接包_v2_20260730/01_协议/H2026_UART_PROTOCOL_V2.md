# H2026 三板 UART 协议 v2

版本：v2.0，2026-07-30

## 1. 为什么升级到 v2

v1 的帧结构和 CRC 可以继续使用，但业务字段存在四个问题：

1. K230 的发送周期与 YOLO 推理周期绑定，图传或垃圾回收卡顿会直接造成控制数据卡顿。
2. `vision_age_ms` 同时表示“链路多久没包”和“球多久没被识别”，无法区分串口断线与暂时丢球。
3. MSPM0-B 没有角度传感器，继续发送 `rod_angle_cdeg` 会让队友误以为它是真实测量值。
4. A 下发的超时时间可能被错误值关闭，因此超时应由 B 本地固化，而不是由通信命令决定。

v2 保留 `AA 55 + version + type + sequence + length + payload + CRC16`，协议版本改为
`0x02`，并重新定义三个运行期数据包。v1、v2 载荷不兼容，接收端必须拒绝错误版本。

当前优先冻结的是 K230 -> B 的 `VISION_SAMPLE`。`A_COMMAND` 和 `B_STATUS` 是给单片机队友的
推荐交接格式；若其控制工程已有成熟接口，可由单片机队友统一调整，但不得反向要求K230承担PID或机构控制。

## 2. 控制职责

| 节点 | 唯一职责 | 不应承担 |
|---|---|---|
| K230 | YOLO11 检球、像素到毫米标定、LCD、RTSP、50 Hz 发布最新测量 | 不运行滚球 PID，不决定车辆动作 |
| MSPM0-B | 接收球位、100 Hz 滚球控制、42步进机构、采集并转发8路循迹红外 | 不运行车辆电机 PID |
| MSPM0-A | 任务状态机、循迹、车辆电机闭环、给 B 下发目标球位和车辆加速度参考 | 不直接控制滚球执行器 |

这样划分的原因是：图传允许卡顿，但控制不允许卡顿；车辆与滚球各自在本地闭环，任一串口异常时都能执行本地安全动作。

## 3. 电气和链路

两条链路均使用 `115200 baud, 8N1, 3.3 V TTL, 无流控`，三板必须共地。

| 链路 | 方向 | 推荐频率 |
|---|---|---:|
| K230 -> B | 单向 `VISION_SAMPLE` | 目标 50 Hz，实测不得低于 25 Hz |
| A -> B | `A_COMMAND` | 固定 100 Hz |
| B -> A | `B_STATUS` | 固定 100 Hz |

K230 端固定使用庐山派标准版带锁GH1.25串口2座：`T=GPIO11/UART2_TXD` 接B的RX，
`G=GND`与B共地。首版为单向链路，`R=GPIO12/UART2_RXD`和`V=5V`均不连接。
B端接任意一个由其 `.syscfg` 配置的3.3V UART RX。不要在协议UART中混入日志文本。

选择这组UART2是因为庐山派官方推荐GH1.25串口2座，带锁结构适合运动小车；UART4的多组排针
存在摄像头I²C或音频复用。CanMV官方还明确UART0用于系统，UART1、UART2、UART4可供用户使用。
没有GH配套线时，可临时使用同一个UART2外设的40Pin物理11脚GPIO5 TX和物理9脚GND；
两套物理引脚只能二选一。

## 4. 通用帧

| 偏移 | 字段 | 长度 | 说明 |
|---:|---|---:|---|
| 0 | `SOF0` | 1 | 固定 `0xAA` |
| 1 | `SOF1` | 1 | 固定 `0x55` |
| 2 | `version` | 1 | v2 固定 `0x02` |
| 3 | `message_type` | 1 | 消息类型 |
| 4 | `sequence` | 1 | 每发一包加 1，自然回绕 |
| 5 | `payload_length` | 1 | 0 到 32 |
| 6 | `payload` | N | 小端序 |
| 6+N | `crc16` | 2 | 低字节先发 |

CRC 为 CRC-16/CCITT-FALSE：多项式 `0x1021`，初值 `0xFFFF`，不反射，无异或输出。
计算范围从 `version` 到载荷末尾，不含帧头和 CRC。`123456789` 的校验值必须为 `0x29B1`。

`sequence` 只用于统计丢包和重复包；超时计时只允许由版本、长度、CRC 和消息类型都正确的包刷新。

## 5. `0x10 VISION_SAMPLE`：K230 -> B

载荷 10 字节。

| 偏移 | 类型 | 字段 | 含义 |
|---:|---|---|---|
| 0 | `int16` | `x_mm` | 球相对摆杆中心 O 的位置，右侧执行器端为正 |
| 2 | `uint8` | `confidence` | 0 到 100 |
| 3 | `uint8` | `flags` | 见下表 |
| 4 | `uint16` | `frame_id` | 每完成一次新推理才加 1；重复发送同一测量时不变 |
| 6 | `uint16` | `sample_age_ms` | 发送时，该推理结果已经产生了多久 |
| 8 | `uint16` | `inference_ms` | 本次推理耗时，仅用于性能诊断 |

`flags`：

| 位 | 名称 | 说明 |
|---:|---|---|
| 0 | `VALID` | 下列质量条件全部通过，可进入控制 |
| 1 | `CALIBRATED` | 像素到毫米标定已完成 |
| 2 | `IN_ROI` | 球心和框尺寸位于摆杆合理区域 |
| 3 | `SINGLE_TARGET` | 只有一个合理钢球目标 |
| 4 | `MODEL_READY` | YOLO11 已初始化 |
| 5 | `CAMERA_READY` | 摄像头工作正常 |

`VALID` 必须同时满足：模型和相机正常、已标定、置信度达标、球在 ROI、没有多球歧义、没有不合理的位置跳变。

K230 的 UART 发送器以 20 ms 为目标周期发布“最新测量快照”，与 YOLO 测量内容解耦。若推理只有 20 fps，
50 Hz 串口会重复 `frame_id`，同时增大 `sample_age_ms`。B 只在 `frame_id` 变化时更新滤波器，
但每个合法串口包都可以刷新链路在线时间。若 CanMV 主循环不能稳定达到 50 Hz，允许实际发送频率
降到 25 至 30 Hz，但必须实测最坏间隔，并保留 150 ms 失联保护。

## 6. `0x30 A_COMMAND`：A -> B

载荷 10 字节。

| 偏移 | 类型 | 字段 | 含义 |
|---:|---|---|---|
| 0 | `uint8` | `mode` | 见下表 |
| 1 | `uint8` | `flags` | 见下表 |
| 2 | `int16` | `target_x_mm` | 球目标位置，建议限制在 `-110..+110 mm` |
| 4 | `int16` | `vehicle_speed_ref_mm_s` | A 的车辆速度指令，用于诊断/增益调度 |
| 6 | `int16` | `vehicle_accel_ref_mm_s2` | A 的纵向加速度指令，可作为 B 的前馈 |
| 8 | `uint16` | `command_id` | 只有命令语义改变时才加 1 |

`mode`：

| 值 | 名称 | B 的行为 |
|---:|---|---|
| 0 | `SAFE_IDLE` | 禁止滚球闭环，不主动寻找球 |
| 1 | `HOME` | 可选的执行器参考建立；当前无零位开关时由B自行定义 |
| 2 | `BALANCE` | 闭环保持 `target_x_mm` |
| 3 | `LEVEL_HOLD` | 回到标定水平位置并保持 |
| 4 | `DIAGNOSTIC` | 仅在架空和人工监护时使用 |

`flags`：

| 位 | 名称 | 说明 |
|---:|---|---|
| 0 | `ENABLE` | 允许 B 输出执行器脉冲 |
| 1 | `ESTOP` | 最高优先级，立即禁止新运动并锁存故障 |
| 2 | `CLEAR_FAULT` | 仅在 `ENABLE=0`、`ESTOP=0` 且 `command_id` 更新时处理一次 |
| 3 | `ACCEL_VALID` | 加速度参考有效，B 才允许使用前馈 |

B 本地固定命令超时为 200 ms。通信包不再携带可变超时，防止错误命令关闭保护。

## 7. `0x20 B_STATUS`：B -> A

载荷 26 字节。

| 偏移 | 类型 | 字段 | 含义 |
|---:|---|---|---|
| 0 | `uint8` | `state` | `BOOT/HOMING/READY/ACTIVE/DEGRADED/FAULT/ESTOP` |
| 1 | `uint8` | `flags` | 球、循迹、执行器参考、链路等快速状态 |
| 2 | `int16` | `ball_x_mm` | 最近一次有效球位 |
| 4 | `int16` | `ball_error_mm` | `target_x_mm - ball_x_mm` |
| 6 | `int32` | `actuator_position_steps` | 从B建立的参考点累计的步数估计，不是角度测量 |
| 10 | `int16` | `control_output_permille` | 滚球控制输出，范围 `-1000..1000` |
| 12 | `int16` | `line_error` | 黑线在车体右侧为正 |
| 14 | `uint8` | `line_bits` | bit0=车体最左 S1，bit7=车体最右 S8 |
| 15 | `uint8` | `reserved` | 固定 0 |
| 16 | `uint16` | `fault_bits` | 故障位 |
| 18 | `uint16` | `vision_rx_age_ms` | 距上一个合法视觉串口包的时间 |
| 20 | `uint16` | `ball_valid_age_ms` | 距上一个可用于控制的新球位的时间 |
| 22 | `uint16` | `command_rx_age_ms` | 距上一个合法 A 命令的时间 |
| 24 | `uint16` | `command_id_echo` | 最近执行的命令编号 |

快速状态位：

| 位 | 名称 |
|---:|---|
| 0 | `BALL_VALID` |
| 1 | `LINE_VALID` |
| 2 | `ACTUATOR_REFERENCE_VALID`，由B的人工初始化或机构参考方案决定 |
| 3 | `CONTROL_ACTIVE` |
| 4 | `VISION_LINK_OK` |
| 5 | `A_LINK_OK` |
| 6 | `HOME_SWITCH_ACTIVE`，当前无开关时固定为0 |

故障位：

| 位 | 故障 |
|---:|---|
| 0 | 视觉链路超时 |
| 1 | 球丢失超时 |
| 2 | A 命令超时 |
| 3 | 执行器位置参考无效 |
| 4 | 参考建立过程超时（未使用自动归零时保持0） |
| 5 | 执行器软件行程越界 |
| 6 | 执行器端部限位触发 |
| 7 | 两个互斥限位同时触发 |
| 8 | 循迹传感器无效 |
| 9 | UART 接收缓冲溢出 |
| 10 | 协议错误过多 |
| 11 | 急停已锁存 |
| 12 | 步进位置不可信/疑似丢步 |

当前没有电气限位，故障位6、7以及快速状态位6在现阶段固定为0。

## 8. 本地周期和安全动作

| 条件 | 接收节点 | 动作 |
|---|---|---|
| 视觉合法包超过 150 ms 未到 | B | `VISION_LINK_TIMEOUT`，禁止滚球 PID；参考可信时才允许限速回水平 |
| `sample_age_ms` 或 `ball_valid_age_ms` 超过 120 ms | B | `BALL_VALID=0`，积分清零，输出缓降 |
| A 命令超过 200 ms 未到 | B | 退出 `ACTIVE`，停止继续加大倾角；参考可信时限速回水平 |
| B 状态超过 200 ms 未到 | A | 车辆受控减速停车 |
| 任何急停 | A/B | 立即禁止新增驱动命令；不得把“自动回中”当急停动作 |
| 执行器位置参考无效 | B | 是否允许闭环由单片机队友的机构方案决定，并通过状态位明确上报 |

推荐任务周期：

- B 步进脉冲：硬件定时器；
- B 滚球控制：100 Hz；
- B UART 解析和状态机：1 ms 调度；
- A 车辆电机速度环：按现有编码器方案，建议 500 Hz 或更高；
- A 循迹决策：100 到 200 Hz；
- 串口 ISR：只收发字节或操作环形缓冲区，不在 ISR 内做 CRC、PID 和阻塞发送。

## 9. 当前无电气零位开关

当前左右结构已经确认为球槽机械挡片，不是电气限位或零位开关。42步进电机的水平参考、软件行程、
丢步处理和控制参数由MSPM0-B队友负责，不让K230视觉接口依赖这些实现细节。

`actuator_position_steps` 仍只是B报告的开环步数估计。B可把人工水平初始化或自己的参考建立结果
通过 `ACTUATOR_REFERENCE_VALID` 上报。若以后增加零位开关，再考虑：

1. 使用至少一个常闭零位开关，断线也能被检测；
2. 标定“零位开关到水平位置”的固定步数；
3. 设置软件最小/最大步数和速度、加速度限制；
4. 每次正式测试前重新归零；
5. 若发生堵转或疑似丢步，停止闭环并重新归零。

协议层不强制具体归零硬件，以免视觉端越权约束单片机实现；但断电、碰撞或步进丢步后参考可能丢失，
此风险应由B状态和故障位对A明确报告。

## 10. 解析器要求

接收器必须：

1. 支持任意分片和连续多帧；
2. 长度不超过 32；
3. CRC 或版本错误后滑动重新搜索 `AA 55`，不能丢弃后续整段数据；
4. 半包字节间隔超过 5 ms 时清除半包；
5. 错误包不得刷新安全超时；
6. 对序号跳变、CRC 错误、溢出分别计数，用于赛前压力测试。

本包的 Python 和 C 参考实现均按上述规则设计。
