# 双轮编码器速度 PI 闭环准备

这个模式让左右轮分别根据编码器反馈自动调整 PWM，使两边的“每 100 ms 编码器计数”接近同一个目标。它是从双轮开环测试到正式循迹控制之间的过渡步骤。

## 当前状态：只能用于软件准备

当前没有小车硬件，下面这些参数只是离线模型占位值，尚未经过实车标定：

| 参数 | 当前值 | 含义 |
|---|---:|---|
| 采样周期 | 100 ms | 每隔100 ms读取并清零编码器 |
| 目标速度 | 10计数/100 ms | `DUAL_SPEED_TARGET_COUNTS`，必须按实车修改 |
| 初始PWM | 600 | `DUAL_SPEED_FEEDFORWARD_PWM` |
| PWM下限 | 400 | 运行时最低输出 |
| PWM上限 | 900 | 防止离线参数造成大输出 |
| Kp | 18 | 每差1个计数的比例修正量 |
| Ki | 6 | 每个采样周期的积分修正量 |
| 积分限幅 | ±100 | 防止长时间失速导致积分饱和 |

预编译固件文件名带有 `unvalidated`，表示“编译通过但没有实车验证”。在完成开环计数测量前，不要烧录运行。

## 安全逻辑

- 两只车轮必须悬空并固定车身。
- 上电后 SW2 必须连续释放 500 ms 才能解锁。
- 按住 SW2 运行；松开后同一个 10 ms 主循环内拉低 PB16/STBY 并把双轮 PWM 清零。
- 停止时按 SW3 切换前进/后退；运行时不允许改变方向。
- SW4 任意一次检测到按下都会锁存急停，复位前不能重新启动。
- 启动时先用 PWM 600，之后每 100 ms 执行一次左右独立的整数 PI。
- PI 输出限制在 400～900，并使用条件积分防止输出饱和时继续累积。
- 继续复用双轮保护：无反馈、单侧掉线、编码器方向错误或持续速度差都会锁存故障。

接线与上一阶段相同，详见 `docs/DUAL_MOTOR_DIAG_GUIDE.md`。

## OLED与串口

OLED 第3、4行分别显示左右轮的计数和当前PWM，例如：

```text
SPEED PI RUN
T:10 DIR:F A
L:+010 P:0582
R:+010 P:0672
```

串口仍使用 CH340、115200、8N1：

```text
SPEED T=10 DIR=F ARM=1 RUN=1 FAULT=NONE dL=+10 pL=582 dR=+10 pR=672
```

## 小车回来后先测目标计数

1. 先烧录并通过单轮测试固件 `car_final_ccs_motor_diag.out`。
2. 再烧录双轮开环固件 `car_final_ccs_dual_motor_diag.out`，不要先用闭环固件。
3. 两轮悬空，按住 SW2 运行约2秒；忽略启动后的前500 ms。
4. 从串口记录后续约10组 `dL`、`dR`，分别求绝对值平均数。
5. 前进和后退各测一次。如果前进计数不是正数、后退不是负数，先修正编码器符号或接线。
6. 初始目标建议取左右平均数中较小的那个整数。例如左轮平均18、右轮平均15，则先把目标设为15。
7. 修改 `user/dual_speed_diag.c` 顶部的 `DUAL_SPEED_TARGET_COUNTS`，重新编译闭环固件。

## 第一次闭环实测顺序

1. 车轮悬空、固定车身，确保线束不会碰到轮胎。
2. 先不给电机主电源供电，烧录重新标定目标后的闭环固件。
3. 测试 SW4 锁存急停，再复位并让 SW2 释放500 ms。
4. 接通电机主电源，按住 SW2 约0.5秒后松开，确认立即停止。
5. 再运行2秒，观察左右计数、左右PWM和故障状态。
6. 两边计数稳定接近目标且没有振荡后，再测试后退。
7. 连续10次短时运行都通过后，才能把这套 PI 接入正式循迹控制。

## 初步调参判断

- 计数接近目标但恢复太慢：小幅增加 Ki，每次只增加1～2。
- PWM和计数来回快速摆动：先减小 Kp，每次减少2～3。
- 长时间缓慢来回摆动：减小 Ki。
- 一启动就达到900并报无反馈：不要继续运行，检查电机电源、PB16/STBY、编码器和目标计数。
- 左右PWM差很多但计数接近：可能是两边机械阻力、电机或驱动差异，需要先检查硬件，不要只靠增大PI参数掩盖。

任何一次只调整一个参数，并保存串口记录，不能同时修改 Kp、Ki、目标计数和 PWM 范围。
