# E2025 循迹闭环适配层

## 当前结论

E2025 状态机已经具备“循迹任务 → 左右轮目标计数 → 双轮速度 PI → 电机 PWM”的完整软件通路，但默认仍然关闭：

```c
#define E2025_OFFLINE_SIMULATION 1
#define E2025_ENABLE_CASCADE_TRACKING 0
```

因此当前默认固件不会转动电机。离线模式初始化时使用 `motor_safe_init_disabled()`，主循环每个 10 ms 控制周期也会再次把左右 PWM 清零并将 PB16/STBY 拉低。

## 数据通路

1. TIMG8 每 10 ms 读取并清零左右编码器计数。
2. 读取八路循迹传感器，`bit0`～`bit7` 对应 D1～D8，黑线为 1。
3. 循迹外环每 10 ms 生成左右轮目标计数。
4. 适配层累计 10 次编码器增量，形成一组 100 ms 实际计数。
5. 左右轮整数 PI 每 100 ms 更新一次 PWM。
6. 编码器保护检查无反馈、单侧丢失、方向错误和按目标比例计算的速度偏差。

当循迹外环要求某一侧目标为 0 时，该侧 PWM 会在当前 10 ms 周期立即变成 0，不会等到下一次 100 ms PI 更新。保护器也不会把“目标本来就是 0”的车轮误判为编码器掉线。

## 安全行为

- SW4/PB27 在任务运行时作为原始电平急停，不等待按键消抖；按下后当周期关闭 PB16/STBY。
- 急停和编码器故障均锁存，必须复位芯片才能清除。
- 从停止切换到运行时，先写入左右 PWM/方向，再拉高 PB16/STBY。
- 任务停止、任务不需要循迹或发生故障时，先拉低 PB16/STBY，再清零两路 PWM。
- 云台 STEP/DIR 与激光 GPIO 仍未接入真实输出。

## 当前占位参数

这些数值只通过软件模型，尚未经过实车验证：

| 项目 | 占位值 |
|---|---:|
| 直行目标 | 左 10、右 10 计数/100 ms |
| 普通循迹目标范围 | 7～13 计数/100 ms |
| PI 前馈 PWM | 600 |
| PI 最小/最大 PWM | 400/900 |
| PI Kp/Ki | 18/6 |

在完成车轮悬空的开环计数测量之前，不允许把新适配层用于落地行驶。

## 离线回放

```powershell
python offline_tools\e2025_drive_adapter_sim.py
```

回放检查以下行为：

- 禁用时输出始终为 0；
- 10 个 10 ms 增量正确合成一个 100 ms 样本；
- 直角转弯时单轮在当周期停止；
- 目标为 0 的车轮不会触发假掉线；
- 两侧无编码器反馈会锁存并停止；
- SW4 急停同周期生效并锁存；
- 默认配置仍是离线模式且功能开关为 0。

结果位于 `output/e2025_drive_adapter_sim/summary.json`。

## 硬件回来后的启用顺序

1. 使用编码器诊断固件，手转车轮确认左右计数和正负号。
2. 使用单轮低 PWM 诊断，确认方向、PB16/STBY 和驱动接线。
3. 使用双轮诊断记录 PWM 600 时左右轮每 100 ms 的实际计数。
4. 修正目标计数、PWM 上下限和 PI 参数，再悬空验证 7、10、13 三档。
5. 只把 `E2025_OFFLINE_SIMULATION` 改为 0，先验证旧 `track1()` 硬件路径。
6. 车轮悬空且 SW4 可随时急停时，再把 `E2025_ENABLE_CASCADE_TRACKING` 改为 1。
7. 最后才落地，从低速直线开始验证，再测试左右偏移、丢线和直角弯。

当前阶段只完成代码接入、离线回放和编译验证，不代表实车已经通过。
