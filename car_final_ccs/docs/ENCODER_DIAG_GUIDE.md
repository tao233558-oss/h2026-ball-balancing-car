# 编码器手动旋转安全诊断

这个模式只读取编码器，不会主动转动电机。左右PWM持续为0，PB16/STBY持续拉低。

## 编码器接线

| 车轮 | A相 | B相 | 计数方式 |
|---|---|---|---|
| 左轮/编码器1 | PA12 | PA13 | A上升沿+B下降沿，x2计数 |
| 右轮/编码器2 | PA24 | PA15 | A上升沿+B下降沿，x2计数 |

## 当前默认状态

源码默认仍运行E2025离线安全模式：

```c
#define APP_PROFILE_E2025        1
#define APP_PROFILE_ENCODER_DIAG 0
```

单独编译好的诊断固件：

`output/firmware/car_final_ccs_encoder_diag.out`

## 上板前准备

1. 断开电机主电源；如果无法断开，至少把车轮悬空。
2. 确认PB16连接电机驱动STBY。
3. 接好编码器电源、GND和四根信号线。
4. 接上XDS110以及天猛星Type-C。
5. 烧录编码器诊断固件。
6. 串口使用CH340对应端口，115200、8N1。

## OLED显示

- 第一行：`ENC DIAG SAFE`
- 第二行：最近约100ms的左、右轮增量。
- 第三行：左轮累计值。
- 第四行：右轮累计值。

代码已经应用比赛程序使用的方向符号。用手把车轮按“小车前进方向”转动时，理想结果是
对应轮的增量和累计值都增加；向后转动时应减小。

## 串口输出示例

```text
ENC RAW1=-12 RAW2=-11 APP_L=+12 APP_R=+11 TOTAL_L=+125 TOTAL_R=+119
```

- `RAW1/RAW2`：中断函数产生的原始计数。
- `APP_L/APP_R`：应用方向修正后的100ms增量。
- `TOTAL_L/TOTAL_R`：方向修正后的累计值。

## 分步检查

1. 两只轮子不动：左右增量应稳定为0，累计值不应自己快速变化。
2. 只向前转左轮：只有`APP_L`明显为正，`APP_R`应接近0。
3. 只向后转左轮：只有`APP_L`明显为负。
4. 对右轮重复相同测试。
5. 同时向前转两只轮：`APP_L`和`APP_R`都应为正。

如果向前转时某一侧为负，不要同时交换很多线。只修改`user/encoder.h`中的对应符号：

```c
#define ENCODER_LEFT_APP_SIGN  (-1)
#define ENCODER_RIGHT_APP_SIGN (-1)
```

把错误一侧的`-1`改为`1`后重新编译。若某侧完全不计数，优先检查供电、共地、A/B信号线
以及编码器输出电平，不要先调PID。

## 通过标准

- 静止时无明显自增。
- 左右轮互不串扰。
- 向前均为正，向后均为负。
- 慢速连续转动时计数方向不反复跳变。

满足这些条件后，才进入低PWM单轮电机测试。
