# 给下一位 Codex 的首条提示词

把下面整段直接复制给新的 Codex：

---

你现在接手 2026 电赛 H 题“车载平衡滚球运动控制系统”。请先完整阅读本交接包中的：

1. `00_先读_整车项目交接说明.md`
2. `02_硬件接线与操作.md`
3. `03_版本与实测记录.md`
4. `04_如何编译烧录与切换主程序.md`
5. `05_关键文件SHA256.md`
6. `赛题与外部交接资料/H题_车载平衡滚球运动控制系统.pdf`

完整 STM32 工程在 `STM32F407完整Keil工程`，Keil 工程入口是 `project/MDK(V5)/Project.uvprojx`。当前 `app/main.c` 是已经恢复、编译、烧录成功的 V17 平衡基线。先计算 SHA256，必须等于交接表中的值；再不改代码执行一次 Build，确认 0 error/0 warning。不要直接覆盖 V17，每次修改前创建版本化 `.saved` 副本。

硬件是单片 STM32F407VET6、两轮差速小车、四路数字红外循迹、编码器、OLED、4 个按键、单路步进电机摆杆、K230 摄像头。赛题规定凹槽内钢球位置检测必须用摄像头，正式测试不能在水管上加 JY61P/MPU6050 等传感器。

当前事实：

- V17 平衡程序可让钢球从 0 去 +5 cm，再折返去 -5 cm，但最终静差仍可能约 -1 cm、+1.5 cm，未完全达标。
- V20/V21/V22 退化，最后出现只向右调一下就停在 +2 cm，已经回退 V17。
- 循迹完整代码在 `app/main_stage41_4ch_line_v20_flowing_curve.c.saved` 和 `app/main_stage49_v1_fixed_route.c.saved`。四路传感器左到右为 S1 PB1、S2 PB0、S3 PC5、S4 PC4，白 0 黑 1。
- 循迹能跑完一圈，稳定版本约 50～51 s，后续约 40 s，还没达到 20 s。
- K230 使用物理 40Pin 第 11 脚 GPIO5/TX，接 STM32 PA3/USART2_RX，9600 baud，ASCII `[x,y]\r\n`；当前控制主要使用 x。
- K230 三点像素标定：左端 37，中心 351，右端 658，对应 -125/0/+125 mm。
- 步进：PA6 STEP、PA7 DIR、PA5 SLP、PA4 RST。正步数车尾上升，小球向负 x/左侧加速。约 258 step/°；机械启动死区约正向 288、反向 253 step。

首要目标不是凭感觉继续改参数，而是：

1. 审计 V17 的停止条件、坐标符号、速度估算、视觉丢帧处理和静摩擦补偿，解释为何未到 -5 cm 就停止。
2. 建立可重复测试日志：每 20～50 ms 记录时间、原始 x、换算 mm、滤波位置、速度、目标、误差、步进目标、步进实际位置、视觉 age、状态机阶段和停止原因。可通过 USB CDC 输出，OLED 只显示关键数据，避免 OLED 刷屏干扰控制。
3. 先在静止车上完成第 3 题：0→+50 mm→-50 mm，≤5 s，两个目标误差绝对值≤10 mm，且最终必须真正在 -50 mm 附近稳定，不允许“提前判定完成”。
4. 每个候选版本都保留源码、Build log、Flash log、HEX 和实测结果；失败时可一键回退 V17。
5. 第 3 题可靠后，再把循迹与平衡合并为统一的非阻塞状态机，定时中断/系统节拍驱动，禁止长延时。

不要声称“已完成”直到实车至少连续 5 次满足时间和误差。每次准备让我操作硬件时，明确告诉我：断电还是上电、需要接哪些线、按哪个键、OLED 应显示什么、要回报哪几个数值。

## 建议新 Codex 首次检查命令

PowerShell：

```powershell
$env:ARM_TOOL_VARIANT='mdk_lite'
Get-FileHash -Algorithm SHA256 '.\STM32F407完整Keil工程\app\main.c'
& 'E:\Downloads\Keil5\UV4\UV4.exe' -b '.\STM32F407完整Keil工程\project\MDK(V5)\Project.uvprojx' -j0
```
